# Components

Components are independently installable units under `components/<name>/`.

## Current Components

- `hypr`: Hyprland config and screenshot helper.
- `waybar`: Waybar JSONC config and CSS style.
- `wofi`: Wofi launcher config.
- `kitty`: Kitty config split into fonts, keys, tabs, window, and main include file.
- `mako`: Notification daemon config.
- `nvim`: Neovim package installation and local LazyVim-based config.
- `opencode`: Official opencode installer without repository-managed config.
- `theme`: Links palette files and applies generated theme output.

## Layout

Typical component layout:

```text
components/<name>/
├── install.sh
└── config/
```

The current implementation does not use component templates. Theme-dependent output is generated by `bin/dots-theme-apply`.

## Install Contract

Each `components/<name>/install.sh` should:

- Be executable.
- Use `set -euo pipefail`.
- Source `bin/dots-lib`.
- Use `dots_link` or `dots_copy` instead of raw file operations.
- Support `DOTS_DRY_RUN=1` through helpers.
- Avoid deleting user files.
- Keep component-specific logic inside the component.

## Adding A Component

1. Create `components/<name>/install.sh`.
2. Add config files under `components/<name>/config/`.
3. Use `dots_link` for editable user config files.
4. Add required packages to the relevant `packages/*.txt` group.
5. Add the component name to `COMPONENTS` in `hosts/current/components.conf` if it should be installed by `--all`.
6. Run `./install.sh --component <name> --dry-run`.

Components may install their own required packages when a package group is not the right fit. Prefer distro packages for distro-provided tools and keep external installers explicit in the component script.
